# zxc - CLI Coding Assistant

## Overview

A terminal-based AI coding assistant that talks to any OpenAI-compatible Chat Completions API (e.g. `llama-server`). It provides an interactive chat loop in which the model can read files, list directories, edit and write files, and run shell commands, looping automatically on tool calls until it produces a final response.

## Requirements

- [Bun](https://bun.sh/) to run the project
- [Glow](https://github.com/charmbracelet/glow) — an external binary used to render markdown responses; checked at startup and required
- A running server exposing `/v1/models` and `/v1/chat/completions` (OpenAI-compatible, SSE streaming)

## Project Structure

```
src/
  index.ts       - Entry point; runs the agent and forwards events to the UI
  agent.ts       - Core agent loop (async generator of AgentEvent)
  tools.ts       - Tool definitions + implementations (read, list, edit, write, bash)
  api.ts         - Chat Completions API: chat() SSE stream, listModels(), summary()
  config.ts      - Configuration management (~/.zxc/zxc.json)
  history.ts     - Chat history: in-memory messages + persisted history files
  ui/
    ui.ts        - Event-driven state machine (prompt / progress / tool / response)
    prompt.ts    - Readline input loop, /model and /resume commands
    summary.ts   - Live "model(thinking)" progress line (elapsed, tokens, reads, lists)
    output.ts    - Raw stdout helpers (write, log, section, reset)
    colors.ts    - Dracula palette via chalk
    glow.ts      - Renders markdown through the glow binary
```

## How It Works

- **Agent loop** (`agent.ts`): `run()` is an async generator. Each iteration either asks the user for input (and pushes a user message) or, after a tool call, sends the accumulated conversation back to the model. It streams the response, accumulates `tool_calls` deltas by index, executes each tool, pushes the assistant message (with `tool_calls`) and `tool`-role messages into history, and loops until the model stops calling tools. Network errors are retried indefinitely.
- **Streaming** (`api.ts`): `chat()` POSTs to `${baseUrl}/v1/chat/completions` with `stream: true` and `stream_options.include_usage`, parses SSE lines into `ChatEvent`s (content, `reasoning_content`, tool-call deltas, usage), and yields them as an async generator.
- **Events → UI** (`ui/ui.ts`): `index.ts` consumes `AgentEvent`s and calls `trigger()`, a small state machine that renders prompts, a live thinking summary, tool banners, and glow-rendered responses.
- **History** (`history.ts`): Messages are OpenAI `ChatCompletionMessageParam`s, kept in memory and mirrored to a file once the first assistant response arrives. The filename slug is generated by asking the model for a hyphen-delimited chat summary (`summary()` in `api.ts`). At startup, `AGENTS.md` from the current working directory (if present) is injected into the conversation as a user message — so this file doubles as the agent's project context.

## Key Concepts

- **Tools**: Five tools, each an OpenAI function-tool definition plus a `run(args)` implementation returning a string:
  - `read` — read a file's contents
  - `list` — list a directory (defaults to cwd)
  - `edit` — replace the first exact-match occurrence of a string; on a mismatch it shows a diff and offers to perform the edit by hand
  - `write` — create or overwrite a file; parent directory must exist
  - `bash` — run a shell command via `bash -c`; output is truncated to first/last 10 lines past 20 lines
- **User confirmations**: `edit`, `write`, and `bash` ask the user to confirm after the operation (or before, for `bash`); denying with a reason rolls back file changes and feeds the reason back to the model.
- **Config** (`~/.zxc/zxc.json`): `model`, `systemPrompt`, `baseUrl`. Created with defaults on first run: the first model from `/v1/models`, the built-in system prompt, and `http://localhost:8000` (or the `LLAMA_BASE_URL` environment variable).
- **Slash commands**: `/model` picks a model from the server's model list; `/resume` loads a saved history file from `~/.zxc`.
- **System prompt**: Defines agent behavior and tool-usage guidelines; sent as the first message of every conversation.

## Development Guidelines

- Avoid comments in code - make it self-explanatory
- Run the app with `bun run start`; there is no test suite
- Types for API messages come from the `openai` package; keep message shapes as `OpenAI.ChatCompletionMessageParam`
- Errors surfaced to the model should be plain strings prefixed with `Error:`, so the model can react to them
- The UI is raw ANSI on `process.stdout` — don't introduce frameworks that take over the terminal
